## When to build new component?

To ensure our Design System has only items that are relevant, follow these rules when considering
building a new component:

### 🧩 Reusability

- ✅ The component should be abstract enough to be reused by other teams (in a different context).
- 🚫 Avoid adding if it's a one-off layout hack or experiment.

### 🎯 Clear purpose

- ✅ The component has to have a specific purpose, that no other component can replicate.
- 🚫 If purpose varies per context (like completely different actions, visuals, semantics), keep it
  local.

### 🎨 Visual + Behavioural Stability

- ✅ The component uses our tokens, is accessible and all needed states are defined. It's overall
  consistent with the rest.
- 🚫 Never add custom solutions as components.

:::info
If the component you need is similar to something we already have in place, consider building a
**variant** instead.
:::
