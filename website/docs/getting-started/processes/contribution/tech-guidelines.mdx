## Tech guidelines for component creation/updates

1. Work together with the Flamingo engineers to ensure code consistency and best practices
   ([Team & comms](/getting-started/team-and-comms)).
2. Once your are "done", please follow our [QA](/getting-started/processes/contribution/qa) guide.

## Component requirements

| Area | Requirement |
| --- | --- |
| Use cases | All component types & states are available (i.e. Active, Tapped, Disabled, Selected, Loading, ...). Error states are available. |
| Visual design & token usage | Component looks and behaves as in design and uses tokens, **never custom** overwrites. |
| Matching variants | Semantic variants (i.e. primary, secondary, tertiary) are consistent with the system. |
| LTR & RTL | Component works in both setups. |
| Sizing & responsiveness | Components resize and behave correctly in different container and viewports sizes. |
| Accessibility | Ensure the component meets the minimum accessibility standards. |
