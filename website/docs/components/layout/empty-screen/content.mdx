# Content

<ComponentTabs basePath="/components/layout/empty-screen" />

- **Title**: state plainly what's missing — "No deliveries yet" rather than something vague or
  overly clever.
- **Description**: only add one if it genuinely helps — explaining why the screen is empty, or
  what the user can do next. Skip it if the title already says everything needed.
- Keep both short. This isn't the place for lengthy explanations — if a user needs more context,
  that belongs in a help article, not the empty state itself.
