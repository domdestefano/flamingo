## Component

## Description

- You cannot have a bottom sheet on top of another bottom sheet.
- You can plug any element in the bottom sheet, excluding other overlay elements, except for the
  tooltip.
- They are elevated higher than the screen's content underneath to convey a clear hierarchy to
  the user.
- Can be dismissed by tapping the area outside (Scrim).

## Properties

| Property | Details |
| --- | --- |
| Scrolled state | Whether the sheet's content has been scrolled (changes elevation/header treatment). |
| Show Graphic Block | Optional — toggles a leading illustration. |
| Show Stack | Optional — toggles the content area. |
| Show Action Container | Optional — toggles the actions area. |
| Show 2nd Action | Optional — toggles a secondary/dismissing action. |
| Show Left icon button | Optional — toggles a leading icon button (e.g. back). |

## Bottom sheet vs. Dialog

Like the dialog, bottom sheets present a set of choices while blocking interaction with the
rest of the screen. The main difference between the two is:

- **Content** — for longer content, Flamingo recommends using a bottom sheet, since it allows
  the sheet to have more content than a dialog thanks to its scrollable functionality.
- **Focus** — a dialog stays in the centre of the view and grabs all of the user's attention.
  This is relevant for high priority error messages or for actions/information that are
  absolutely required to be interacted with in order to continue within the user's flow.

## Bottom sheet vs. Action picker

When you want the user to select among different actions of the same prominence, use the Action
picker. Use the bottom sheet when the actions are of different importance or when it requires
contextual information on top of the actions.
