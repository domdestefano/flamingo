# Guidelines

<ComponentTabs basePath="/components/progressors-and-charts/stepper" />

## Usage

You can use icons to hint visually what the steps consist of — an icon-based approach may make the
stepper flow feel easier to complete for the user, since it doesn't show a strict progression
divided into numbers.

Numbered steps are used mostly when you want to clearly show an ordered progression. Number-based
steppers give a clear sense of order and help the user focus more on the task.

The advance through progressive steps should always be triggered by UI elements such as buttons.
Depending on the prominence of the progressive action, you can use secondary buttons. For
regressive actions, we recommend tertiary or icon buttons.

Some steps might be locked because the user needs to complete the previous steps first. You can
use a tooltip to explain why a step is locked.

## Placement

Steppers can be placed freely in the interface, or inside other container-like components, e.g.
cards, bottom sheets, or main sheets. When placed within components, it's recommended to keep a
few steps to avoid UI clutter.

## Use cases

### # of Steps

Avoid having too many steps when the user's tasks are quite extensive. This helps avoid cognitive
overload and the fear that content wouldn't be saved if all the tasks aren't completed.

<DoDontTable
  doText="Group steps that refer to the same thing."
  dontText="Long and numerous steps can overwhelm the user."
/>

### Step indicator

Steppers can use either icons or numbers. Avoid mixing the two together, as they can create
confusion.

<DoDontTable
  doText="Use clear iconography to avoid visually mixing indicator types."
  dontText="Mixing icons and numbers makes understanding the progression harder."
/>

### Back and forth

In order to move through steps, present trigger elements that allow the user to progress, and
regress if needed. We recommend relying on the back button in the header to regress, and a primary
button at the bottom to progress.

<DoDontTable
  doText="Use a primary button to advance the main action of the flow. When steps are available at the same time, provide the trigger action with each step."
  dontText="Don't place multiple actions within the same step."
/>

<CautionTable text="You can have progressive actions stacked horizontally, but be mindful of content and layout." />
