## Description

Steppers convey progress through steps and should be used when you want the user to complete a
task divided into smaller logical steps, or progress through multiple locations (e.g. a rider
delivery journey). You can use the stepper to guide the user through a series of information to
fill in or actions to take — for instance, to guide the user through adding their phone number and
confirming their identity: (1) provide a new phone number, (2) confirm their identity.

- They can be mandatory or optional. If optional, the user needs to have the option to skip them.
- They can present icons or numbers.
- They can encapsulate further content inside through the stack.

## Properties

| Property | Details |
| --- | --- |
| # of Steps | Varies from 2 to 9 — the number of steps the user can go through. |
| Step indicator | Icons or numbers, to represent the steps. |
| State | **Completed/Past** — the step is completed by the user. **Available/Present** — the step is available for the user to interact with. **Unavailable/Future** — the step is not available for the user to interact with yet. |
| Suffix | The elements on the right side. |
| Stack | The container where you can place further content within the Stepper. |
| Title | Can be either text or a Tag. |
| Subtitle | Secondary text element. |
| Caption | Tertiary text element. |

## Variations

### Step indicator

The step indicator communicates the status of each step. Use numbers to display the sequential
step order, or icons to use visual state icons. While you can choose whichever icons make sense
for your use case, we recommend a checkmark for Completed and a lock for Unavailable steps.

1. Numbers
2. Icons

### # of Steps

Choose between 2 and 9 steps to match the complexity of your user flow. The Stepper height scales
automatically — use fewer steps for simpler flows, more steps for multi-stage processes.

1. Few-step process
2. Multi-step process

### Step states

Each step has one of three distinct states: **Completed** — the step was finished by the user,
**Available** — the current active step the user is on, **Unavailable** — a future step that is
locked and not yet accessible.
