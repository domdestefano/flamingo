## Usage

Use the primary button for high emphasis — for the primary, most important, or most common action
on a screen.

## Placement

1. **Bottom of the screen**: the primary button should usually be placed at the bottom of the page,
   sticky if necessary, to enhance the reachability of the main action.
2. **On the screen**: primary buttons can also be used in the content sections.
3. There should be **normally only one (or none) primary action per screen**.

## Use cases

### Don't use for non-primary actions

Use primary buttons only for the most important actions you'll need a user to do. Repetitive or
less important actions can be indicated by using different button types. Always consider the main
purpose of a screen.

**Do** — a screen whose purpose is to show personal data has no main action a user has to take,
so the edit button is displayed in the header as an icon, an optional and not-required task.

**Don't** — using a primary button for editing data gives the impression that the user has to do
this action though (this is not the case here).

### Multiple use on the screen

Primary buttons can only be used once on a screen, as they represent the most important action of
the screen. Use secondary or tertiary buttons for less important actions.

**Do** — use primary buttons combined with secondary or tertiary ones, instead of using two of them,
based on the importance of the actions you want the user to perform.

**Don't** — avoid combining multiple primary buttons, as this may be confusing for the user and
create a hardly scannable UI.

### Resizing

Buttons can resize horizontally based on the content. Not vertically. Primary and Secondary buttons
in Flamingo do not support multi-line.

**Do** — buttons only resize horizontally and use as few words as possible in sentence case.

**Don't** — buttons do not resize vertically. Make sure to also check translations, since a longer
translated label is the most common cause of an unwanted second line.

### Stack

When the primary button is combined with another action to express the dualism of choice, try to
provide a preferred (primary) and an alternative (secondary or tertiary) option.

**Do** — when stacking buttons, keep the primary button on top of (or first in reading order to) the
secondary or tertiary one.

**Don't** — don't place two secondary buttons above each other, as they fight for attention and
priority.

For the `button.small` variant, you can horizontally stack it with other elements as the size of
the elements are small enough to accommodate longer labels. Be always mindful of the length and
translation of the text.

**Do** — use horizontal stacks only with small primary buttons and short labels.

**Don't** — medium to long labels can easily create readability issues. Always consider
translations.
