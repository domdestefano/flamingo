# Guidelines

<ComponentTabs basePath="/components/buttons/primary-button" />

## Usage

Use the primary button for high emphasis — for the primary, most important, or most common action
on a screen.

## Placement

1. **Bottom of the screen**: the primary button should usually be placed at the bottom of the page,
   sticky if necessary, to enhance the reachability of the main action.
2. **On the screen**: primary buttons can also be used in the content sections.
3. There should be **normally only one (or none) primary action per screen**.

  doImage="/img/components/primary-button/primary-button-placement-do.png"
  doText="Place the primary button at the bottom of the screen, sticky if the content scrolls, so it stays reachable."
  dontImage="/img/components/primary-button/primary-button-placement-dont.png"
  dontText="Don't show more than one primary button on the same screen — if several actions all compete for the user's attention, none of them actually reads as the primary one."

## Use cases

### Don't use for non-primary actions

Use primary buttons only for the most important actions you'll need a user to do. Repetitive or
less important actions can be indicated by using different button types. Always consider the main
purpose of a screen.

<DoDontTable
  doImage="/img/components/primary-button/primary-button-non-primary-do.png"
  doText={<>A screen whose purpose is to show personal data has no main action a user has to take, so the edit button is displayed in the header as an icon — optional and not required.</>}
  dontImage="/img/components/primary-button/primary-button-non-primary-dont.png"
  dontText={<>Using a primary button for editing data gives the impression that the user has to do this action, though that's not actually the case here.</>}
/>

### Multiple use on the screen

Primary buttons can only be used once on a screen, as they represent the most important action of
the screen. Use secondary or tertiary buttons for less important actions.

<DoDontTable
  doText="Use primary buttons combined with secondary or tertiary ones, instead of using two of them, based on the importance of the actions you want the user to perform."
  dontText="Avoid combining multiple primary buttons — it's confusing for the user and creates a hardly scannable UI."
/>

### Resizing

Buttons can resize horizontally based on the content. Not vertically. Primary and Secondary buttons
in Flamingo do not support multi-line.

<DoDontTable
  doText="Buttons only resize horizontally, using as few words as possible in sentence case."
  dontText="Buttons don't resize vertically. Check translations, too — a longer translated label is the most common cause of an unwanted second line."
/>

### Stack

When the primary button is combined with another action to express the dualism of choice, try to
provide a preferred (primary) and an alternative (secondary or tertiary) option.

<DoDontTable
  doImage="/img/components/primary-button/primary-button-stack-do.png"
  doText="When stacking buttons, keep the primary button on top of (or first in reading order to) the secondary or tertiary one."
  dontImage="/img/components/primary-button/primary-button-stack-dont.png"
  dontText="Don't stack two primary buttons above each other — they fight for attention and priority, and only one action can really be primary."
/>

For the `button.small` variant, you can horizontally stack it with other elements as the size of
the elements are small enough to accommodate longer labels. Be always mindful of the length and
translation of the text.

<DoDontTable
  doText="Use horizontal stacks only with small primary buttons and short labels."
  dontText="Medium to long labels can easily create readability issues. Always consider translations."
/>
