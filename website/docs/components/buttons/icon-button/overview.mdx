## Component

<ComponentImage src="/img/components/icon-button/icon-button-overview.png" alt="Icon button variants: type, size, and state" />

Icon buttons are used to communicate actions that users can take. They're typically placed
throughout the UI, in places like modals, forms, cards, and nav bars.

Use the icon button for **minimal emphasis** — for the most minimal, common actions on a screen.
Every action that isn't secondary or primary needs to be tertiary or icon-based. Icon buttons are
for very minimal actions that users could interact with on discovery, not need.

## Properties

| Property | Details |
| --- | --- |
| Type | **Tertiary**: the default type for clickable icons on a flat background — the most common type, used for standard tappable icons (navigation, expand/collapse, info/help, etc.). **Secondary**: used for actions that are contextually relevant in the user flow, but not part of the core path. **Primary**: reserved for rare use cases, to highlight important or unread content. |
| Size | The component is available in 2 sizes, depending on the prominence designers want to give to the action and the size of the element it refers to — the container for both sizes is **36×36px**. For most standard use cases we recommend `button.icon.big`. The main exception is `button.icon.medium`, used with the `tertiary` type if a tappable icon is paired with small text (such as a caption). |
| State | **Active**: the button is clickable. **Pressed**: the button is being pressed. **Inactive**: the button is not interactive and not clickable. |

Because there's no text label, only use an icon button where its icon is unambiguous — if there's
any doubt a user will recognise what it does, use a labelled button (Tertiary or Secondary) instead.

### Clickable area

The icon button's tappable area extends beyond its visible background, so it still meets the
standard touch target size even for the Medium size variant — don't shrink the hit area to match
the visible circle.
